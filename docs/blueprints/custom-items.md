# Custom Items & CustomModelData

CraftingBlueprints works with both vanilla Minecraft items and custom items provided by resource packs or plugins such as **ItemsAdder**, **Oraxen**, and custom model data frameworks.

---

## 1. CustomModelData on Physical Blueprints

If you have a custom 3D model for your physical blueprint item (such as an ancient scroll, a stone tablet, or a holographic disc):

```yaml
singles:
  ancient_katana_blueprint:
    blueprint: DIAMOND_SWORD
    name: "<gold>Ancient Katana Scroll</gold>"
    item:
      material: PAPER
      custom_model_data: 5012 # Matches your resource pack model predicate
      glowing: true
```

When a player receives this blueprint, their client will render the custom 3D model matching `CustomModelData: 5012`.

---

## 2. Unlocking Custom Plugin Items

If your server features custom weapons or armor generated by external plugins:

### Bukkit CustomModelData Matching
```yaml
singles:
  ruby_broadsword_blueprint:
    # Target item specification
    blueprint: DIAMOND_SWORD
    name: "<red><bold>Ruby Broadsword Blueprint</bold></red>"
    extra:
      custom_model_data: 1045
```

### Compatibility with ItemsAdder & Oraxen
CraftingBlueprints intercepts craft events by examining the resulting `ItemStack`. If you have custom recipes registered via ItemsAdder or Oraxen, CraftingBlueprints can gate those recipes just like vanilla ones:

1. Identify the internal ID or result item of the recipe.
2. In your YAML blueprint, specify the result item material.
3. If using [Recipe Restrictions](../mechanics/recipe-restrictions.md), add the item identifier to `restricted-items`.

---

## 3. Custom Metadata & NBT (`extra`)

The `extra:` key allows you to attach custom data for server scripts (e.g. Denizen, Skript) or external plugins:

```yaml
singles:
  shadow_dagger:
    blueprint: IRON_SWORD
    extra:
      required_level: 45
      category: "ASSASSIN"
      tradeable: false
```
