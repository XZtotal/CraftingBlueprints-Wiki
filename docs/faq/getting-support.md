# Reporting Bugs & Getting Help

If you encounter unexpected behavior or need assistance with CraftingBlueprints, follow this guide to get support quickly.

---

## 1. Before You Submit a Ticket

To help us resolve your issue promptly, please run through this quick checklist:

* [ ] Verify that your server is running a supported engine (Paper or Purpur 1.18.2 – 1.21.x).
* [ ] Run `/cb validate` to rule out syntax errors in your blueprint YAML files.
* [ ] Check your console logs for any error stacktraces.

---

## 2. Opening an Issue on GitHub

We track all bug reports and feature requests via our official GitHub repository:

👉 **[Submit a Bug Report](https://github.com/XZtotal/CraftingBlueprints-Wiki/issues/new?template=bug_report.yml)**
👉 **[Submit a Feature Request](https://github.com/XZtotal/CraftingBlueprints-Wiki/issues/new?template=feature_request.yml)**

---

## 3. What Information to Provide

When reporting an issue, always include:

1. **Exact Server Software & Version**: (e.g. `Paper 1.20.4 build 498`).
2. **CraftingBlueprints Version**: Run `/cb status` to find your version.
3. **Database Engine**: Whether you are using SQLite or MySQL.
4. **Console Logs**: Use a paste service like [mclo.gs](https://mclo.gs/) or [hastebin](https://hastebin.com/) to share your logs. Never post raw screenshots of console text.
5. **Step-by-Step Reproduction**: Detailed steps explaining how to trigger the problem.
